## 1. Regras puras e regras de apresentação

### Identidade, ordenação e união

- `data class SessionKey(val origin: String, val provider: String, val account: String, val sessionId: String)`; `fun serialize(): String`; `fun deserialize(value: String): SessionKey`: `C/data/ApiModels.kt:18-25`. A chave inclui os quatro campos. Serialização é JSON compacto, nesta ordem: `origin`, `provider`, `account`, `sessionId`, todos strings. Não concatenar componentes por separadores. Deserialize exige os quatro. Teste `T/SessionIdentityTest.kt:15` cobre `/`, `:`, aspas, origem/provedor distintos.
- `fun byLastMessage(sessions: List<SessionItem>): List<SessionItem>`: `C/data/Unread.kt:18`. Ordenação decrescente por `replies.lastOrNull() ?: lastAt ?: 0L`. Usa último elemento, **não máximo**, de replies. Replies existente vence lastAt mesmo se lastAt for maior. Empates mantêm ordem de entrada pela ordenação estável Kotlin. Teste `T/UnreadTest.kt:23-27` fixa reply 90 versus lastAt 95, fallback 50 e ausência 0; não fixa empate explicitamente.
- `fun mergeSessions(states: Map<String, ReadingState>, filter: String?): List<SessionItem>`: `C/data/Unread.kt:20-21`. Filtra chaves de origem por igualdade exata quando filter não nulo; concatena listas na ordem de iteração do mapa. Não ordena, deduplica ou mistura identidades entre origens. Filtro desconhecido dá lista vazia. Teste `T/data/ServersTest.kt:28-36`.
- `fun serverLabel(origin: String): String`: `C/data/Unread.kt:23-28`. Host de URL, IPv6 entre colchetes; omite só porta padrão do protocolo. Não inclui esquema. Teste `T/data/ServersTest.kt:38-43` fixa HTTP 80/HTTPS 443 e portas alternativas.

### Nomes e JSON

Defina `O = origem string exata`, `K = SessionKey.serialize()`, `S = sha256_utf8(K)` (64 hex), `G = sha256_utf8(O)[0..16]` (16 hex, não 16 bytes). Serialização de K deve preservar ordem e escaping Kotlin para produzir mesmo hash; hash de JSON reordenado diverge (`C/data/ApiModels.kt:19`, `J/data/LocalStateStore.jvm.kt:60,83,171`).

**`<dataDir>/local_state.json`** é objeto JSON compacto. Chaves são opcionais; estado inicial sem arquivo equivale a `{}` (`J/data/LocalStateStore.jvm.kt:42-43`). Campos existentes:

```text
{
  "servers": [string origin, ...],
  "conversation_generation": string UUID,
  "last_session": string contendo K (JSON serializado dentro de string),
  "message_<G>_<S>": {
    "text": string,
    "revision": int64,
    "attachments": [
      {"uri": string, "name": string, "mime": string,
       "size": int64|null, "persistent": boolean}
    ],
    "operation"?: {"id": string|null,"status": string,"revision": int64,"error"?: string},
    "control"?: {"id": string|null,"status": string,"revision": int64,"error"?: string}
  },
  "view_<G>_<S>": "all"|"prompts"|"no_tools",
  "deliver_<G>_<S>": "aside"|"followUp"|"steer",
  "seen_replies_<G>": { "<S>": int64 server_epoch_ms, ... }
}
```

- `conversation_generation` só é criada em clear(), não no primeiro addServer. Se ausente, interpolação Kotlin no nome de cache usa texto literal `null`. Não gerar UUID espontaneamente ao abrir estado legado/novo: mudaria caminhos. `J/data/LocalStateStore.jvm.kt:101,145`.
- Message encoding/decoding: `J/data/LocalStateStore.jvm.kt:47-58`. Defaults sem valor/objeto válido: text="",revision=0,attachments=[],operation/control=null. Operation objeto com id ausente/null => null, status ausente/null=>unknown,revision ausente/inválida=>0,error opcional. Attachment malformado é descartado individualmente; uri/name/mime obrigatórios, size long opcional/null, persistent só boolean true. Encode sempre escreve text/revision/attachments; size explícito null; op id explícito null; omite op/control se null e error se null. Não existe objeto `draft` no JSON em disco.
- `updateMessage(key, update)` exige origem presente em servers, senão erro `Connection changed`; modifica atomicamente sob mutex. `message(key)` não exige origem conectada; key inexistente dá MessageLocalState default. `usesAttachment(uri)` varre todos message_* e compara URI exata. `J/data/LocalStateStore.jvm.kt:84-90`.
- `last_session` não é objeto embutido, mas **string JSON**. Getter deserialize inválido=>null. Setter público sem token não valida servers; setter interno valida origem/token/sequence. Null remove campo, não escreve JSON null. `J/data/LocalStateStore.jvm.kt:91-98`.
- `servers` mantém ordem de adição; add idempotente por igualdade exata, não valida URL. Remove filtra igualdade exata. Não normalizar strings silenciosamente no store. `J/data/LocalStateStore.jvm.kt:61-62,114-124`.
- `sessionView` e `sessionDeliverAs` validam valor e caem no default global quando ausente/inválido. Setters ignoram valor fora das listas, mas valor válido com origem ausente lança Connection changed. seen lê só longs parseáveis, default mapa vazio. `J/data/LocalStateStore.jvm.kt:167-181`.

**`<dataDir>/conversation-<generation-or-null>-<G>-<S>.json`**: `J/data/LocalStateStore.jvm.kt:101-111`, codec `C/data/LocalStateStore.kt:30-51`.

```text
{
  "truncated": boolean,
  "entries": [
    {"id": string,"kind": string,"text": string,
     "title"?: string,"toolUseId"?: string,"truncated"?: true,"at"?: int64}
  ],
  "summaries"?: { "<entry.id>:<signed-kotlin-text-hash>": string, ... }
}
```

- Guarda últimas 500 entradas em ordem, truncated = entrada truncated-global OU total>500. truncated=false por entrada é omitido; null title/toolUseId/at omitidos. Resumos incluem somente chaves que correspondem às entradas mantidas; se input summaries não vazio mas nada corresponde, escreve summaries={}. Se input vazio, campo omitido.
- Decode usa TerminalEntry.parse (incluindo normalização kind/at) e só resumos strings. Getter exige origem presente; arquivo ausente/inválido=>null. Não persiste reduced; truncation de retenção fica em truncated. Testes `T/ConversationCacheTest.kt:10,21,29`.

### Remoção, limpeza, migração e escritas atrasadas

- `removeServer(origin)` (`J/data/LocalStateStore.jvm.kt:125-141`), NonCancellable sob mutex: remove origem de servers; apaga message/view/deliver com prefixo G e seen_replies_G; apaga last_session só se deserialize válido e origem igual; salva JSON. Incrementa epoch daquela origem e remove written sequences da origem. Apaga arquivos conversation-* terminados .json cujo trecho anterior ao último `-` termina `-G`. Mantém outras origens, conversation_generation, preferências, retry, attachments, avatares e chaveiro/cookies. Essa função **não faz logout sozinha**. Testes `JT/data/LocalStateStoreJvmTest.kt:28-49`; corrida remove/re-add `JT/data/NativeStorageRulesJvmTest.kt:57-88`.
- `clear()` (`J/data/LocalStateStore.jvm.kt:142-154`), NonCancellable sob mutex: lê origens, remove **todo conteúdo** de local_state, cria somente conversation_generation com novo UUID, salva. Incrementa epochs de todas origens conhecidas/anteriores, limpa written. Apaga qualquer arquivo em dataDir cujo basename começa conversation- ou attachment-, sem exigir .json. Mantém local_state.json com nova geração, preferências todas, retry todas, cacheDir/avatars e chaveiro/cookies. Cookies são responsabilidade de SessionCookieStore.clear. Arquivos originais externos de anexos JVM não são removidos. Testes `JT/data/LocalStateStoreJvmTest.kt:51,64`.
- Compatibilidade legado (`J/data/LocalStateStore.jvm.kt:63-79`): se não há servers e há origin legado, cria servers=[origin], renomeia message_/view_/deliver_ seguidos exatamente por 64 hex lowercase para `<prefix><G>_<hash>`, move seen_replies para seen_replies_G, remove origin, salva e **apaga todos arquivos conversation-***. Se servers já existe, não migra, mesmo vazio. Não migra chave de mensagem se sufixo não casa regex. Teste de hash/seen legado `JT/data/LocalStateStoreJvmTest.kt:71-82`.
- Epoch/sequence (`J/data/LocalStateStore.jvm.kt:29-38,93-111,177-181`): epoch por origem default 0; sequence global incrementa por conversationWrite; sessionWritten global e written por SessionKey. Tokens não persistem. Escrita conversa só aceita origem igual à key, epoch atual, origem conectada e sequence > último escrito daquela key. ### Sessão segura e cookies

- `SecureSessionStorage` JVM (`J/data/SessionCookieStore.jvm.kt:11-31`): serviço keyring **`br.com.xlinx.zaplaud`**, conta **`remote-session`**. Um valor string contém cookies de todas origens. `zaplaud.keyring=memory` desativa keyring; erro de criação também usa memória. read tenta chaveiro e cai na memória se não há valor/falha. write atualiza memória antes do chaveiro; erro de gravação só avisa stderr `Zaplaud: chaveiro indisponível, login só nesta execução`, não lança. Clear zera memória e tenta deletar item, ignorando erro. Não há arquivo plaintext de cookie.
- `encodeCookies(cookies: Map<String, String>): String`, `decodeCookies(value: String): Map<String, String>` (`C/data/SessionCookieStore.kt:23-37`): valor de keyring é JSON compacto `{"v":2,"cookies":{"<origin>":"<rendered-Set-Cookie>"}}`. Cookie value é cabeçalho **Set-Cookie renderizado completo**, incluindo atributos, não só valor/token. Decode v cujo primitive content="2" usa cookies objeto; senão legado `{ "origin": string, "cookie": string }`. JSON inválido/estrutura inválida=>mapa vazio. Testes `T/data/ServersTest.kt:17,21`.
- `SessionCookieStore(origin)` (`C/data/SessionCookieStore.kt:40-144`) compartilha lock reentrante, cookies e generations por origem. Construtor relê chaveiro e substitui cookie em memória; se antes havia cookie e persistido não há, incrementa generation. `generation()` é token para rejeitar respostas antigas.
- `saveFromResponse(url: String, headers: List<String>, expectedGeneration: Long)` (`:68-104`): exige generation atual e origem URL exata. Parseia headers e pega último cookie chamado habblaud_remote; ignora outros. Domain, se presente, deve ser host igual ou sufixo de subdomínio. Expiração usa Max-Age sobre expires; expirado limpa origem. Retido remove maxAge e materializa expires absoluto, domain default host, path default diretório do request ou `/`. Atualiza apenas origem no mapa keyring. Falha de storage que efetivamente lança tenta remover origem/limpar e lança IllegalStateException; wrapper JVM normalmente absorve falha keyring e usa memória.
- `requestHeader(url: String): String?` (`:105-121`): cookie expirado é limpo; exige origem exata e HTTPS se secure. Path casa igualdade ou prefixo em fronteira de `/`; retorna apenas `name=value`, não atributos. `clear()` incrementa generation, zera cookie e remove só origem da blob, deletando item se mapa ficou vazio. `clear(expectedGeneration: Long): Boolean` não limpa login novo se token stale. Testes `JT/data/NativeStorageRulesJvmTest.kt:21,41,123` fixam isolamento de origem/secure, resposta tardia e logout que não remove outra sessão.

### Cache de avatares JVM

Fonte completa `J/data/AvatarCache.jvm.kt:9-58`.

- Arquivo: `<cacheDir>/avatars/<sha256_utf8(origin + request-path-with-query)>`, **sem extensão**. Não usa seed como nome direto. Query inclui scale=3 e parts serializado, portanto ordem/encoding participam da identidade.
- `decode(bytes: ByteArray): ImageBitmap?` (`:17-22`): tamanho 24..1 MiB, assinatura PNG de 8 bytes, offset12 chunk type IHDR, big-endian width em offset16=60 e height em20=60. Decoder Skia precisa realmente produzir 60x60. JPEG, PNG 61px, corpo inválido ou >1MiB=>null. Teste `JT/data/AvatarCacheJvmTest.kt:14-25`.
- Memória singleton access-order LinkedHashMap, LRU por acesso; custo width*height*4; limite 4*1024*1024 bytes. Insert substituído desconta bitmap antigo. Remove mais antigos até caber. Bitmap 60x60 custa 14400 bytes. Hit em memória não consulta TTL de disco.
- Read (`:33-40`): memória primeiro. Disco só arquivo regular, mtime com idade **<86.400.000 ms** e size<=1MiB; igualdade de 24h já expira. Mtime futuro não expira. Arquivo inválido/expirado não é removido nesse caminho. Decode válido entra memória.
- Save (`:41-58`): só dados válidos entram cache. Primeiro lembra em memória; em runCatching cria diretório e Files.write direto no arquivo (não protectedWrite/rename). Lista arquivos regulares ordenados por mtime desc, acumula tamanhos e apaga os que fazem total ultrapassar 16MiB. Ordenação não possui desempate explícito para mtime igual. Erro de disco é ignorado; bitmap ainda retornado. Save não remove por TTL, read não atualiza mtime. clear/removeServer de LocalStateStore não removem esse cache nem memória.

## 4. Casos a espelhar no Rust e limites de evidência

- Preservar unidades UTF-16 de text.length, text.take e String.hashCode; usar chars()/hash Rust muda limites e summary keys.
- Preservar recent como lista inclusiva, não apenas sessões encerradas; não ordenar replies para calcular última resposta.
- Preservar desconhecido após POST ambíguo; não repetir mensagens, stop, cast, asides ou comandos automaticamente.
- Preservar separação entre snapshot connection e readingError; terminal offline não torna snapshot offline.
- Preservar formatos existentes de chave/JSON/nome de cache, inclusive generation ausente => `null` e last_session string JSON.
- Testes de search/split, context thresholds, summary UI thresholds, platformDeadline/retryAfterDeadline e seleção visual de avatar não foram localizados como testes dedicados nas suítes listadas. A especificação desses itens vem do código citado, não de execução ou teste inventado.
- Não foram executados builds, linters, testes ou smoke runs. Repositório de origem permaneceu somente leitura; único artefato criado é este contrato em `/tmp`.
